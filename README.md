# screen_color

画面上の決まった位置の色を読み取り、**画面の外周を同じ色の枠で塗る** Windows 用ツールです。

コンフィグ作業用プログラムの小さな状態表示（青＝進行中、黄＝エラー など）を、離れた場所からでも一目で分かるようにするために作りました。複数台のPCを1人で見回るライン作業を想定しています。

- 枠は常に最前面に表示されますが、**クリックは下の画面に素通り**するので作業の邪魔になりません
- 画面の中央は覆いません（上下左右4本の帯のみ）
- 読み取った色をそのまま表示します（色の意味づけはしません）
- **色の変化をログ（CSV）に記録**し、分析レポート（HTML）と集計表（CSV）を出力できます
- 他のウィンドウが重なったときなどの**誤検知を防ぐ仕組み**つき（後述）
- Python 標準ライブラリのみで動作（追加インストール不要）

## 動作環境

- Windows 10 / 11
- Python 3.8 以上（tkinter 付きの標準インストール）
- モニター1枚を想定

## ファイル構成

| ファイル | 役割 |
|---|---|
| `pick_point.py` | 座標確認ツール。F8 で座標とウィンドウ名、F9 で色を `config.json` に保存 |
| `status_border.py` | 本体。指定座標の色を定期的に読み取り、画面外周を同じ色にする |
| `analyze.py` | ログを分析し、レポート（HTML）と集計表（CSV）を出力 |
| `demo_config_app.py` | デモ用の仮コンフィグプログラム（状態を色で表示する小さなウィンドウ） |
| `make_sample_logs.py` | デモ用のサンプルログ（10台 × 5日分）を作成 |
| `color_log.py` | ログの書き込み・読み込み |
| `screen_utils.py` | 共通処理（ピクセル読み取り・設定ファイル読み書き） |
| `config.json` | 設定ファイル |

## 使い方

### 1. ダウンロード

```
git clone https://github.com/aeeiouuuu/screen_color.git
cd screen_color
```

### 2. 色を読み取る座標を決める

```
python pick_point.py
```

1. 小さなウィンドウにマウス位置の座標・色・ウィンドウ名が表示されます
2. コンフィグプログラムの状態表示（色が変わる部分）の **真ん中あたり** にマウスを合わせます
3. **F8** を押すと、座標とウィンドウ名（`window_title`）が `config.json` に保存されます
4. 状態表示がそれぞれの色（進行中・エラー・完了など）になったときに **F9** を押すと、その色が `labels` に追加されます。名前（「色1」など）は `config.json` で書き換えてください
5. **Esc** で終了

その後、`config.json` の `roles` に「完了」と「エラー」がどの名前かを書きます（後述）。

### 3. 本体を起動する

```
python status_border.py
```

画面の外周に枠が表示され、指定座標の色に合わせて色が変わります。

**終了方法：** 起動したコンソールで `Ctrl+C`、またはコンソールを閉じる。

色が変わるたびに `logs/<PC名>_<日付>.csv` に記録されます。

### 4. 分析レポートを出す

```
python analyze.py
```

`reports/` に次のファイルができ、レポートが自動でブラウザに開きます。
レポートの上部で **期間（最新日・直近7日・日付指定など）と PC を絞り込めます**。

| ファイル | 内容 |
|---|---|
| `report_<日時>.html` | 分析レポート。ブラウザの印刷から PDF 保存もできます |
| `segments_<日時>.csv` | 色が続いた区間の一覧（PC・色・開始・終了・秒数） |
| `summary_<日時>.csv` | PC × 色 ごとの回数・合計・平均・最長時間 |

レポートの内容：
- **主な数字**：処理台数・処理ペース（台/時）・サイクルタイム・エラー率・エラー対応待ち・取り外し待ち・見えなかった時間
- **気づき（自動抽出）**：処理ペースが遅い／エラー率が高い／待ち時間が長い／見えなかった時間が多いPC
- **PC別の比較**：上の数字をPCごとに並べた表
- **日別の処理台数**
- **対応待ち時間**：「エラー」「完了」の表示が続いた時間の分布と、長かった上位10件
- **時間帯別**：処理台数・エラー率・待ち時間を時間帯ごとに
- 色ごとのまとめ / PC別の時間の内訳 / PCごとのタイムライン（見えなかった時間は斜線）

用語：
| 用語 | 意味 |
|---|---|
| 処理台数 | 「完了」になった回数 |
| サイクルタイム | 「完了」から次の「完了」までの時間（中央値）。昼休みなど監視を止めた時間はまたがない |
| エラー率 | 100台あたりのエラー回数 |
| エラー対応待ち | 「エラー」表示が続いた時間 ＝ 人が気づいて対応するまでの目安 |
| 取り外し待ち | 「完了」表示が続いた時間 ＝ 機器を外して次に進むまでの目安 |
| 見えなかった時間 | 他のウィンドウが重なるなどで、状態を読めなかった時間 |

**10台分をまとめて分析するには：** 各PCの `logs/` フォルダの中身を1つのフォルダに集めて
`python analyze.py --log-dir 集めたフォルダ` を実行します。
`config.json` の `log_dir` を共有フォルダ（例：`\\server\share\logs`）にしておけば、集める手間もなくなります。

## 設定（config.json）

```json
{
  "x": 405,
  "y": 261,
  "window_title": "Config Tool",
  "border": 25,
  "interval_sec": 0.5,
  "stable_samples": 2,
  "color_tolerance": 40,
  "pc_name": "",
  "log_dir": "logs",
  "labels": {"#808080": "待機", "#0078d7": "進行中", "#ffc000": "エラー", "#00b050": "完了"},
  "roles": {"done": "完了", "error": "エラー"}
}
```

| 項目 | 内容 |
|---|---|
| `x`, `y` | 色を読み取る画面上の座標（ピクセル） |
| `window_title` | 対象ウィンドウのタイトル（一部でOK）。空なら重なりを確認しない |
| `border` | 外周の枠の太さ（ピクセル） |
| `interval_sec` | 色を確認する間隔（秒） |
| `stable_samples` | 同じ色が何回続いたら「変わった」とみなすか |
| `color_tolerance` | `labels` の色とどれくらい違っても同じ色とみなすか（0〜441） |
| `pc_name` | ログに記録するPC名（空ならWindowsのコンピューター名） |
| `log_dir` | ログの保存先フォルダ |
| `labels` | 色に名前を付ける。ここにある色だけを状態として受け付けます。空なら読み取った色すべてを使う |
| `roles` | どの色が「完了」(`done`)・「エラー」(`error`) かを、`labels` の名前か色コードで指定。処理台数・エラー率・待ち時間の分析に使います |

## 誤検知の対策

他のウィンドウが重なったり、マウスカーソルやツールチップが一瞬かかったりすると、違う色を読んでしまい、外周の色も記録も集計もずれます。そのため次の対策をしています。

| 対策 | 内容 | 必要な設定 |
|---|---|---|
| 重なりの確認 | 読み取り位置の一番手前にあるウィンドウが対象プログラムか、タイトルで確認。違えば「見えていない」扱い | `window_title` |
| 知っている色だけ受け付け | `labels` に近い色だけを状態とみなし、それ以外は「見えていない」扱い | `labels` |
| ちらつき対策 | 同じ色が続けて読めたときだけ「変わった」とみなす | `stable_samples` |
| 二重カウント防止 | 見えていない間も枠は最後の色のまま。同じ色で戻ったら続きとして扱い、回数を増やさない | （自動） |

見えていなかった時間はログに `HIDE` / `SHOW` として残り、レポートの「見えなかった時間」に出ます。この値が大きいPCは集計の信頼性が下がるので、画面の配置を見直してください。

全PCで画面構成が同じなら、1台で作った `config.json` を他のPCにコピーするだけで使えます。

## デモ

本物のコンフィグプログラムがなくても動作を試せます。

```
python demo_config_app.py
```

1. 「Config Tool (DEMO)」ウィンドウが開き、待機（灰）→ 進行中（青）→ エラー（黄）/ 完了（緑）を自動で繰り返します
2. 「この位置を config に設定」を押すと、状態表示の座標・ウィンドウ名・デモ用の色の名前と役割が `config.json` に保存されます
3. 別のコンソールで `python status_border.py` を起動すると、画面の外周がデモの状態に合わせて色が変わります
4. デモのウィンドウの上に別のウィンドウを重ねると「見えなくなりました」と表示され、色の変化として数えられないことを確認できます

レポートのデモ（10台 × 5日分のサンプルデータ）：

```
python make_sample_logs.py
python analyze.py --log-dir sample_logs
```

## 注意点

- 読み取り座標が枠と重なると枠自身の色を読んでしまいます（起動時に警告が出ます）。座標を内側にするか `border` を小さくしてください
- 対象ウィンドウが他のウィンドウに隠れたり最小化されたりすると、正しい色を読めません
- `status_border.py` を `Ctrl+C` 以外（強制終了など）で止めると、最後の区間は長さが分からないため分析から除外されます
- `labels` の色は `pick_point.py` の F9 で取るのが確実です。手で書く場合も `pick_point.py` に表示される色コードを使ってください
- 座標は画面の実ピクセルで扱っています。拡大率（100%, 125% など）を変えた場合は座標を取り直してください
