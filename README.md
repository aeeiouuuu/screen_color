# screen_color

コンフィグ作業用プログラムの小さな状態表示（青＝進行中、黄＝エラー など）を読み取り、
**画面の外周を同じ色の太い枠で塗る** Windows 用ツールです。
あわせて状態の変化を記録し、**処理台数・エラー率・対応待ち時間などを分析したレポート**を出せます。

複数台のPCを1人で見回るライン作業で、「どのPCがいまどの状態か」を離れた場所から一目で分かるようにするのが目的です。

```
 ████████████████████████████  ← 画面の外周（上下左右の帯）が
 ██                        ██     状態表示と同じ色になる
 ██   +-----------------+  ██     （青＝進行中、黄＝エラー…）
 ██   | Config Tool     |  ██
 ██   | Status: [■]     |  ██  ← この■の色を読み取る
 ██   +-----------------+  ██
 ██                        ██
 ████████████████████████████
```

## 1. できること

| 機能 | 内容 |
|---|---|
| 外周の色表示 | 状態表示の色を 0.5 秒ごとに読み取り、画面の上下左右を同じ色の帯で塗る |
| 作業の邪魔をしない | 帯は常に一番手前に出るが、**クリックは下の画面にそのまま届く**。画面の中央は覆わない |
| 記録 | 色が変わるたびに、時刻と色をCSVファイルに記録する |
| 分析レポート | 処理台数・サイクルタイム・エラー率・対応待ち時間などを、ブラウザで見られるレポートにまとめる。期間やPCで絞り込める |
| 誤検知の対策 | 他のウィンドウが重なったときなどに、間違った色を数えない |

追加のインストールは不要です（Python 本体だけで動きます）。

## 2. 準備（最初に1回）

### 2-1. Python が入っているか確認

1. キーボードの `Windowsキー` を押し、「cmd」と入力して Enter（黒い画面＝コマンドプロンプトが開きます）
2. 次のように入力して Enter

   ```
   python --version
   ```

3. `Python 3.11.3` のように表示されればOKです
   - 「'python' は認識されていません」と出たら、[python.org](https://www.python.org/downloads/) からインストールしてください。インストール画面の最初で **「Add python.exe to PATH」にチェック** を入れるのを忘れずに

### 2-2. このツールをダウンロード

**方法A：git を使う**

```
git clone https://github.com/aeeiouuuu/screen_color.git
```

**方法B：ZIPでダウンロード**

1. https://github.com/aeeiouuuu/screen_color を開く
2. 緑色の「Code」ボタン →「Download ZIP」
3. ダウンロードしたZIPを右クリック →「すべて展開」

好きな場所（例：デスクトップ）にフォルダを置いてください。

### 2-3. フォルダでコマンドプロンプトを開く方法

以降の手順では、**このツールのフォルダでコマンドを入力**します。いちばん簡単な開き方：

1. エクスプローラーで `screen_color` フォルダを開く
2. 上のアドレスバー（フォルダの場所が表示されている所）をクリック
3. `cmd` と入力して Enter

→ そのフォルダでコマンドプロンプトが開きます。

## 3. まずデモで試す

本物のコンフィグプログラムがなくても、付属のデモで動きを確認できます。
**初めての方はここから試すのがおすすめです。**

### 3-1. デモ用のコンフィグプログラムを起動

```
python demo_config_app.py
```

「Config Tool (DEMO)」という小さなウィンドウが開きます。

- 左上の四角（Status）の色が、**待機（灰）→ 進行中（青）→ 完了（緑）またはエラー（黄）** と自動で変わります
- 下のボタンで手動で状態を切り替えることもできます（「自動モード」のチェックを外すと止まります）

### 3-2. 読み取り位置を設定

デモのウィンドウ右下の **「この位置を config に設定」** を押します。
状態表示の座標・ウィンドウ名・色の名前が `config.json` に自動で書き込まれます。

### 3-3. 外周の色表示を起動

**もう1つ**コマンドプロンプトを開き（[2-3](#2-3-フォルダでコマンドプロンプトを開く方法)の方法）、次を入力します。

```
python status_border.py
```

画面の外周に色の帯が出て、デモの状態に合わせて色が変わります。
コマンドプロンプトには次のように表示されます。

```
監視開始: 座標 (405, 261), 間隔 500ms, 枠 25px  (終了は Ctrl+C)
ログ保存先: C:\...\screen_color\logs  (PC名: DESKTOP-XXXX)
色が変わりました: #808080 待機
色が変わりました: #0078d7 進行中
```

**試してみてください：** デモのウィンドウの上にメモ帳などを重ねると「見えなくなりました」と表示され、色の変化として数えられません（[9章](#9-誤検知の対策のしくみ)）。

**終了：** `status_border.py` を動かしているコマンドプロンプトで `Ctrl` + `C` を押します。

### 3-4. レポートのデモ

10台×5日分のサンプルデータを作って、レポートを見てみます。

```
python make_sample_logs.py
python analyze.py --log-dir sample_logs
```

ブラウザでレポートが開きます。サンプルデータは分析の違いが分かるよう、わざと偏らせてあります。

| PC | 設定したクセ |
|---|---|
| LINE-PC03 | 作業が遅い |
| LINE-PC07 | エラーが多い |
| LINE-PC10 | エラーや完了への対応が遅い |

レポートの「気づき」に、これらのPCが自動で挙がるのを確認してみてください。

## 4. 本番の設定（PCごとに1回）

本物のコンフィグプログラムで使うための設定です。
**10台とも画面の配置が同じなら、1台で設定した `config.json` を他のPCにコピーするだけで済みます。**

### 4-1. デモの設定を消す

デモを試した場合、`config.json` にデモ用の色が残っています。
`config.json` をメモ帳で開き、`labels` と `roles` を空にして保存してください。

```json
  "labels": {},
  "roles": {}
```

### 4-2. 読み取り位置とウィンドウ名を保存（F8）

1. コンフィグプログラムを、いつも使う位置に表示しておく
2. 座標確認ツールを起動

   ```
   python pick_point.py
   ```

3. 小さなウィンドウにマウス位置の **座標・色・ウィンドウ名** が表示されます
4. マウスを、コンフィグプログラムの **状態表示（色が変わる部分）の真ん中あたり** に合わせる
   - 端だと文字や枠線の色を拾うことがあるので、真ん中にしてください
5. **F8** を押す →「保存しました」と表示されます（座標とウィンドウ名が `config.json` に入ります）

### 4-3. 状態の色を登録（F9）

座標確認ツールを開いたまま、続けて行います。

1. 状態表示が「進行中」の色になっているときに、マウスを状態表示に合わせて **F9**
2. 「エラー」「完了」「待機」など、**出てくる色すべて**について同じように F9 を押す
3. 終わったら **Esc** で座標確認ツールを閉じる

> **重要：** 登録していない色は「見えていない」として扱われ、記録されません。出てくる可能性のある色は全部登録してください。

### 4-4. 色に名前を付ける

`config.json` をメモ帳で開くと、F9 で登録した色が「色1」「色2」…という名前で入っています。
どの色がどの状態か分かる名前に書き換えます（色コードはそのまま）。

```json
  "labels": {
    "#0078d7": "進行中",
    "#ffc000": "エラー",
    "#00b050": "完了",
    "#808080": "待機"
  },
```

> どの色コードがどの状態か分からなくなったら、もう一度 `pick_point.py` を起動して、状態表示にマウスを合わせると色コードが表示されます。

### 4-5. 「完了」と「エラー」を指定

同じく `config.json` の `roles` に、どの名前が「完了」で、どの名前が「エラー」かを書きます。
**これを書くと、処理台数・エラー率・対応待ち時間が分析できるようになります。**

```json
  "roles": {
    "done": "完了",
    "error": "エラー"
  }
```

### 4-6. 動作確認

```
python status_border.py
```

- 外周の色が、状態表示の色と同じになっているか
- 状態が変わったときに、コマンドプロンプトに「色が変わりました」と出るか
- コンフィグプログラムの上に別のウィンドウを重ねたときに「見えなくなりました」と出るか

を確認してください。起動時に「注意:」や「警告:」が出た場合は [10章](#10-困ったとき) を見てください。

## 5. 毎日の使い方

### 起動

作業を始めるときに、フォルダでコマンドプロンプトを開いて：

```
python status_border.py
```

コマンドプロンプトは**閉じずに**そのままにしておきます（最小化はOK）。

### 終了

コマンドプロンプトで `Ctrl` + `C`。

> 終了するときは、なるべく `Ctrl` + `C` で止めてください。×ボタンで閉じたりPCの電源を切ったりすると、最後の状態がいつまで続いたか分からないため、その分だけ分析から外れます（それ以外の記録は問題なく残ります）。

### ダブルクリックで起動したい場合

フォルダに `start.bat` という名前で次の内容のファイルを作ると、ダブルクリックで起動できます（メモ帳で作成し、「ファイルの種類：すべてのファイル」で保存）。

```bat
@echo off
cd /d %~dp0
python status_border.py
pause
```

さらに、このファイルのショートカットを「スタートアップ」フォルダ（`Windowsキー + R` →`shell:startup` と入力して Enter）に入れると、PCの起動時に自動で立ち上がります。

### 記録されるもの

色が変わるたびに `logs` フォルダに記録されます。ファイルは **PCごと・日ごと** に分かれます。

```
logs/
  DESKTOP-ABC_20261024.csv
  DESKTOP-ABC_20261025.csv   ← 日付が変わると新しいファイル
```

中身（Excel でも開けます）：

```
timestamp,           pc,          event, color
2026-10-25 08:31:08, DESKTOP-ABC, START,
2026-10-25 08:31:09, DESKTOP-ABC, COLOR, #808080
2026-10-25 08:33:37, DESKTOP-ABC, COLOR, #0078d7
2026-10-25 08:40:02, DESKTOP-ABC, HIDE,  covered
2026-10-25 08:40:15, DESKTOP-ABC, SHOW,
```

| event | 意味 |
|---|---|
| START | 監視を開始した |
| COLOR | 状態の色が変わった（color 列が新しい色） |
| HIDE | 状態表示が見えなくなった（他のウィンドウが重なった など） |
| SHOW | また見えるようになった |
| END | 監視を終了した |

## 6. レポートの見方

### レポートを作る

```
python analyze.py
```

`logs` フォルダのログを**全部（全日付・全PC）**読み込んで分析し、`reports` フォルダに次のファイルを作ります。レポートは自動でブラウザに開きます。

| ファイル | 内容 |
|---|---|
| `report_<日時>.html` | 分析レポート。ダブルクリックでいつでも開けます |
| `segments_<日時>.csv` | 「どのPCで、どの状態が、何時から何時まで続いたか」の一覧（Excel用） |
| `summary_<日時>.csv` | PC × 色ごとの回数・合計・平均・最長時間（Excel用） |

> レポートを印刷したい・PDFにしたいときは、ブラウザで `Ctrl` + `P` →（プリンターで「PDFに保存」を選ぶ）。

### 絞り込み

レポートの一番上で、見たい範囲を切り替えられます。切り替えると全部の数字・グラフがその場で計算し直されます。

| 操作 | 内容 |
|---|---|
| 期間 | 「最新日」「直近7日」「直近30日」「全期間」のボタン、または日付を直接指定 |
| PC | PC名のボタンを押すと、表示する・しないが切り替わる。「全て」「解除」で一括切り替え |

例：「PC07 の昨日だけ」→「解除」を押してから「LINE-PC07」を押し、「最新日」を押す。

### 各項目の意味

| 項目 | 意味 | 見るポイント |
|---|---|---|
| **処理台数** | 「完了」になった回数 | 日ごと・PCごとの生産量 |
| **処理ペース（台/時）** | 監視していた1時間あたりの処理台数 | PC間で遅いところはないか |
| **サイクルタイム** | 「完了」から次の「完了」までの時間（中央値） | 1台あたりにかかる実際の時間。標準時間の目安 |
| **エラー率** | 100台あたりのエラー回数 | 特定のPCや時間帯に偏っていないか |
| **エラー対応待ち** | 「エラー」表示が続いた時間 | 人がエラーに気づいて対応するまでの目安 |
| **取り外し待ち** | 「完了」表示が続いた時間 | 完了に気づいて機器を外すまでの目安 |
| **見えなかった時間** | 他のウィンドウが重なるなどで、状態を読めなかった時間の割合 | 大きいと集計の信頼性が下がる |

> 待ち時間は「その色が表示され続けた時間」から計算しています。コンフィグプログラムが自動で再試行する場合なども含まれるので、「人が対応するまでの時間の目安」として見てください。

### レポートの各欄

| 欄 | 内容 |
|---|---|
| 主な数字 | 上の表の数字を、選んだ範囲全体でまとめたもの |
| 気づき（自動抽出） | ほかのPCと比べて差が大きいものを自動で挙げる（処理ペースが85%未満、エラー率が1.5倍以上、待ち時間が3割以上長い、見えなかった時間が3%以上） |
| PC別の比較 | 上の数字をPCごとに並べた表。色が濃いほど値が大きい |
| 日別の処理台数 | 日ごとの処理台数の棒グラフとエラー率 |
| 対応待ち時間 | 待ち時間の長さの分布（〜1分、1〜3分…）と、長かった上位10件 |
| 時間帯別 | 処理台数・エラー率・待ち時間を時間帯（時）ごとに。休憩前後や夕方に悪くなっていないか |
| 色ごとのまとめ | 色ごとの回数・合計時間・割合 |
| PC別の時間の内訳 | 各PCでどの状態が何割を占めたか |
| タイムライン | 各PCの状態の移り変わり。帯にマウスを乗せると時刻が出る。斜線は見えなかった時間、空白は監視していなかった時間 |

## 7. 10台分をまとめて分析する

ログは各PCの `logs` フォルダにたまります。10台分をまとめて分析するには、ログを1か所に集めます。
ファイル名にPC名が入っているので、1つのフォルダに混ぜても上書きされません。

### 方法A：手で集める

1. 各PCの `logs` フォルダの中身（CSVファイル）を、USBメモリなどで1つのフォルダ（例：`C:\集計\logs`）にコピー
2. そのフォルダを指定して分析

   ```
   python analyze.py --log-dir C:\集計\logs
   ```

### 方法B：共有フォルダに直接記録する（おすすめ）

社内の共有フォルダがあれば、各PCの `config.json` の `log_dir` をそこにしておくと、集める手間がなくなります。

```json
  "log_dir": "\\\\server\\share\\screen_color_logs",
```

（`\` は2つ重ねて書きます。`\\server\share\...` → `"\\\\server\\share\\..."`）

分析はどのPCからでも：

```
python analyze.py --log-dir \\server\share\screen_color_logs
```

### PC名を分かりやすくする

ログのPC名は、何もしなければ Windows のコンピューター名（`DESKTOP-ABC123` など）になります。
`config.json` の `pc_name` に書くと、その名前で記録されます。

```json
  "pc_name": "LINE-PC01",
```

## 8. 設定ファイル（config.json）の説明

`config.json` はメモ帳で開いて編集できます。編集したら、`status_border.py` を起動し直すと反映されます。

```json
{
  "x": 405,
  "y": 261,
  "window_title": "Config Tool",
  "border": 25,
  "interval_sec": 0.5,
  "stable_samples": 2,
  "color_tolerance": 40,
  "pc_name": "",
  "log_dir": "logs",
  "labels": {"#808080": "待機", "#0078d7": "進行中", "#ffc000": "エラー", "#00b050": "完了"},
  "roles": {"done": "完了", "error": "エラー"}
}
```

| 項目 | 内容 | 通常の設定方法 |
|---|---|---|
| `x`, `y` | 色を読み取る画面上の位置（ピクセル） | `pick_point.py` の F8 |
| `window_title` | 対象ウィンドウのタイトル（一部だけでもOK）。空にすると重なりの確認をしない | `pick_point.py` の F8 |
| `border` | 外周の帯の太さ（ピクセル）。目立たせたいなら大きく | 手で編集 |
| `interval_sec` | 色を確認する間隔（秒） | そのままでOK |
| `stable_samples` | 同じ色が何回続いたら「変わった」とみなすか。ちらつきが多いなら大きく | そのままでOK |
| `color_tolerance` | 登録した色とどれくらい違っても同じ色とみなすか（0〜441）。うまく認識しないときは大きく | そのままでOK |
| `pc_name` | ログに記録するPC名。空なら Windows のコンピューター名 | 手で編集（任意） |
| `log_dir` | ログの保存先フォルダ | 手で編集（任意） |
| `labels` | 状態として扱う色とその名前。**ここにある色だけが記録される**。空ならすべての色を記録 | `pick_point.py` の F9 ＋ 名前を手で編集 |
| `roles` | `done`（完了）と `error`（エラー）が、`labels` のどの名前か | 手で編集 |

> `config.json` を編集するときは、`"` や `,` を消さないよう注意してください。壊れると起動時にエラーになります。

## 9. 誤検知の対策のしくみ

色を読み取る方式なので、状態表示の上に他のものが重なると違う色を読んでしまいます。
そのままだと外周の色も、記録も、処理台数などの集計もずれてしまうため、次の対策をしています。

| 起きること | 対策 | 必要な設定 |
|---|---|---|
| 他のウィンドウが重なる | 読み取り位置の一番手前にあるウィンドウのタイトルを確認し、対象のプログラムでなければ「見えていない」扱い | `window_title` |
| マウスカーソルやツールチップが一瞬かかる | 登録した色に近い色だけを状態とみなす。さらに同じ色が続けて読めたときだけ「変わった」とみなす | `labels`, `stable_samples` |
| 重なりが外れて元に戻る | 見えていない間も外周は最後の色のまま。戻ったときに同じ色なら「続き」として扱い、**回数を二重に数えない** | （自動） |

見えていなかった時間はログに `HIDE` / `SHOW` として残り、レポートの「見えなかった時間」やタイムラインの斜線に出ます。
この値が大きいPCは、コンフィグプログラムの上に他のウィンドウを置かない配置にしてください。

## 10. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 「'python' は認識されていません」と出る | Python が入っていないか、PATH が通っていません。[2-1](#2-1-python-が入っているか確認) を参照 |
| 外周の帯が出ない | `status_border.py` が動いているか、コマンドプロンプトを確認。閉じると帯も消えます |
| 帯の色がずっと変わらない | ① `x`, `y` がずれている → `pick_point.py` で F8 をやり直す　② 色が `labels` に登録されていない → F9 で登録 |
| 「見えなくなりました」が何もしていないのに出る | ① `window_title` が実際のタイトルと違う（タイトルが作業中に変わるプログラムなど）→ 変わらない部分だけにする（例：`"Config Tool"`）　② 登録していない色が出ている → F9 で登録（コマンドプロンプトに `unknown #xxxxxx` と出ていればその色） |
| 起動時に「警告: 読み取り座標が枠に隠れます」 | 読み取り位置が画面の端すぎて、外周の帯と重なっています。帯の色を読んでしまうので、`border` を小さくするか、コンフィグプログラムを内側に置いて座標を取り直す |
| 起動時に「注意: window_title が未設定」 | 重なりの確認が働きません。`pick_point.py` で F8 を押せば設定されます |
| 起動時に「注意: labels が未設定」 | 読み取った色をすべて状態として記録します。誤検知を防ぐには F9 で色を登録してください |
| 画面の拡大率（100%・125%など）を変えたら色がずれた | 座標が変わります。`pick_point.py` で F8 をやり直してください |
| コンフィグプログラムの位置を動かした | 同上。座標を取り直してください |
| レポートに処理台数などが出ない | `config.json` の `roles` が未設定か、`labels` の名前と一致していません（[4-5](#4-5-完了とエラーを指定)） |
| レポートに「ログがありません」 | `logs` フォルダが空か、`--log-dir` の指定が違います |
| `config.json` を編集したら起動しなくなった | `"` や `,` の消し忘れ・付け忘れがないか確認。分からなくなったら `config.json` を削除すれば初期設定に戻ります（設定はやり直し） |
